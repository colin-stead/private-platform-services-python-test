     Context

     DB config is currently hardcoded in three places: BaseHandler.CLIENT =
     MongoClient("mongodb", 27017) plus "Rewards" in

     load_mongo_data.py. Tests currently hit the docker server on :7050 (which

     Findings that shape the design:
     - pytest runs on the host (.venv, Python 3.14, pytest installed); Mongo is
       a docker container with 27017 published.
       The hostname mongodb only resolves inside docker, so on the host the
       tests must use localhost.
     - The server on :7050 is a running container pinned to "Rewards", so tests
       can't make it use "Tests".
       Approach: pytest starts its own in-process Tornado server (port 7051) in
       a background thread, after setting
       os.environ to point at the "Tests" DB. The 7050 server/"Rewards" DB are
       never touched. No docker/compose changes.
     - MONGODB_URI (used by test_connection) is not set anywhere; it will be
       replaced by the shared config.

  database error. The test server now builds a plain
  tornado.web.Application(url_patterns) from the same routes.

  What a reviewer needs to run the tests

  I didn't edit the READMEs, since you said you'd do that.
  1. A MongoDB container running with port 27017 published to the host, for
     example cd source/RewardsService && docker-compose up -d. The 7050 service
     doesn't need to be running.
  2. A host virtualenv with the dependencies: python -m venv .venv &&
     .venv/bin/pip install -r source/RewardsService/requirements.txt.
  3. Port 7051 free. No environment variables are needed, because pytest
     defaults to localhost:27017 and the Tests DB. You can override with
     MONGO_HOST and MONGO_PORT.
  4. Run cd source/RewardsService && ../../.venv/bin/pytest rewardsservice/tests
     -v.

  The tests create and seed the Tests DB themselves.
